新發現的 BLOCKER：兩態顯示 CSS／JS 契約斷裂

目前 CSS 是：

```css
.laoyi-view{display:none;}
.laoyi-view.laoyi-visible{display:block;}
.laoyi-room{...display:flex;...}
```

但 JS 的 `laoyiShowHall()`／`laoyiEnterRoom()` 只切換 `hidden`：

```js
hall.hidden=false;
room.hidden=true;
```

沒有任何地方加入或移除 `laoyi-visible`。

這會造成：

- `#laoyiHall` 即使 `hidden=false`，仍被 `.laoyi-view{display:none}` 隱藏。
- `.laoyi-room{display:flex}` 出現在 `.laoyi-view` 後方、specificity 相同，因此會覆蓋 `display:none`。
- 作者 CSS 的 `display:flex` 也可能覆蓋瀏覽器對 `[hidden]` 的預設隱藏規則，導致 room 在應隱藏時仍顯示。

也就是首訪門廳很可能完全不顯示，問答室則可能一直顯示。現有 40 項測試只檢查節點和 CSS 定義存在，沒有驗證實際 visibility／computed display，因此沒有抓到這個問題。

建議最小修正是統一只使用 `hidden`，移除互相衝突的 display 規則，例如：

```css
.laoyi-view[hidden]{display:none;}
.laoyi-room:not([hidden]){display:flex;}
.laoyi-hall:not([hidden]){display:block;}
```

或者改成 JS 真正維護 `laoyi-visible`，但不要同時混用兩套顯隱狀態。
