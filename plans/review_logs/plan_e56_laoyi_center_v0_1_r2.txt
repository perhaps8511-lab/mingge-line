七路由:`GET /history`、`GET /log`、`GET /study`、`POST /log/seal`、`POST /trace`、`POST /trigger/deepdive`、`POST /trigger/fupan

5. payload 欄位白名單檢查(多餘欄位直接 400)
6. 業務邏輯 → 轉發下游(webhook 或未來的 Dify)
7. 統一用 `json(obj, status)` 輔助函式回應,CORS 由 `corsHeaders()` 處理

```js
async function laoyiSend(text){

  var trimmed=(text||'').trim();
  if(!trimmed) return;
  if(trimmed.length>LAOYI_QUERY_MAX){
```

## 2. C2 — worker.js 新路由 `POST /laoyi/chat`

插入位置:緊接 `/trigger/fupan` 區塊之後(第 567 行 `}` 後)、`POST /` 主閘(第 569 行)之前,維持既有路由由上而下比對的順序慣例。

```js

  }

  }

  const payloadKeys = payloadIsObject ? Object.keys(payload) : [];
  if (payloadKeys.some(k => k !== "query" && k !== "conversation_id")) {
    return json({ error: "Unexpected field in payload", code: "BAD_FIELD" }, 400);
  }

  const rawQuery = payloadIsObject ? payload.query : undefined;
  const query = typeof rawQuery === "string" ? rawQuery.trim() : "";
  if (!query || query.length > 2000) {
    return json({ error: "Invalid query", code: "INVALID_QUERY" }, 400);
  }
  // r1 #14:conversation_id 非字串/不符格式一律 400,不得靜默 slice 變造成另一個 ID
  const rawConvId = payloadIsObject ? payload.conversation_id : undefined;
  let conversationId = "";

      return json({ error: "Invalid conversation_id", code: "INVALID_CONV_ID" }, 400);

        query,

    console.log("Laoyi Dify forward failed", timedOut ? "timeout" : (e.message || e));
    return json({ error: timedOut ? "Dify request timed out" : "Dify request failed",
                  code: timedOut ? "UPSTREAM_TIMEOUT" : "UPSTREAM_ERROR" }, 502);
  } finally {
    clearTimeout(timeoutId);
  }

    console.log("Laoyi Dify forward failed", difyRes.status);
    return json({ error: "Dify request failed", code: "UPSTREAM_ERROR" }, 502);
  }
  let difyData;
  try { difyData = await difyRes.json(); }
  catch (e) { return json({ error: "Dify response parse failed", code: "UPSTREAM_SCHEMA_ERROR" }, 502); }

ength > 0;

    return json({ error: "Dify response malformed", code: "UPSTREAM_SCHEMA_ERROR" }, 502);
  }

  return json({ answer: difyData.answer, conversation_id: difyData.conversation_id }, 200);
```

### N1 — composer 元素與 listener 初始化未閉合

```js
laoyiInput.disabled=busy;
```

計畫也沒有給出可靠的元素綁定：

```js
var laoyiInput = document.getElementById('laoyiInput');

var laoyiThread = document.getElementById('laoyiThread');
```

失節點 fail closed。

### N2 — malformed Dify response 會把內容寫入 Worker log

這行可能把 Dify 回覆、使用者資料或其他上游內容寫進 Cloudflare logs：

```js
console.log(
  "Laoyi Dify response shape invalid",
  JSON.stringify(difyData).slice(0, 200)
);
```

這與「stateless／不留存」及 §6 的資料透明度說明不一致。平台 log 仍是外部留存面。應只記錄非內容型診斷，例如：

```js
console.log("Laoyi Dify response shape invalid", {
  hasAnswer: typeof difyData?.answer === "string",
  hasConversationId: typeof difyData?.conversation_id === "string"
});
```

不得記錄 answer、query、token、userId 或原始 response body。

我接受「本卡不能動 Dify prompt/KB」，但這只證明結構化旗標目前不可做，不能自動授權改弱驗收條件。Regex 可作最薄實作，但須由 Perth 明確接受其 false negative／false positive 邊界及新的 fixture-based DoD。

因此這條是「待 Perth 裁決」，目前仍為 BLOCKER。

### #13 Rate limiting／B3：堅持為放行 BLOCKER

同意不應在 stateless Worker 裡假裝做不可靠的記憶體計數，也同意 Cloudflare 帳號層是合理位置。但「不在 repo 範圍」不等於風險已解除。

可允許 C1–C4 施工，但在真機公開上線前，必須有以下之一：

- Cloudflare Rate Limiting Rule 已建立並留有可驗證證據；或
- Perth 明確接受無 rate limit 上線的成本風險。

另外，「每 token」是否可直接作為 Cloudflare rule key 不能只寫「如」；實際可用的 matching/counting key 要在 B3 執行時查證。

## 三、新發現的 BLOCKER

### N1 — composer 元素與 listener 初始化未閉合

DOM 中按鈕 ID 是 `laoyiSend`，但 `laoyiSetComposerBusy()` 使用的是未定義的 `laoyiSendBtn`：

```js
laoyiInput.disabled=busy;
laoyiSendBtn.disabled=busy;
```

計畫也沒有給出可靠的元素綁定：

```js
var laoyiInput = document.getElementById('laoyiInput');
var laoyiSendBtn = document.getElementById('laoyiSend');
var laoyiThread = document.getElementById('laoyiThread');
```

同時，`initAskLaoyiPage()` 範例只綁門廳兩顆按鈕，沒有明確綁定：

- `laoyiSend` click
- `laoyiInput` keydown
- `laoyiSvcEntry` click

3.1 的頂層 `document.getElementById(...).addEventListener(...)` 還存在 DOM 尚未建立時直接拋錯的風險。這些 listener 應統一在 guarded init 中完成，並對缺失節點 fail closed。

### N2 — malformed Dify response 會把內容寫入 Worker log

這行可能把 Dify 回覆、使用者資料或其他上游內容寫進 Cloudflare logs：

```js
console.log(
  "Laoyi Dify response shape invalid",
  JSON.stringify(difyData).slice(0, 200)
);
```

這與「stateless／不留存」及 §6 的資料透明度說明不一致。平台 log 仍是外部留存面。應只記錄非內容型診斷，例如：

```js
console.log("Laoyi Dify response shape invalid", {
  hasAnswer: typeof difyData?.answer === "string",
  hasConversationId: typeof difyData?.conversation_id === "string"
});
```

不得記錄 answer、query、token、userId 或原始 response body。

## 放行條件

完成以下事項後可再蓋 `APPROVED`：

1. 修正 N1 的元素取得、ID 命名及所有 listener 初始化。
2. 移除 N2 的上游內容 logging。
3. Perth 明確裁決 #6 的 E47 適用範圍。
4. Perth 明確接受 #17 heuristic 與 fixture-based DoD，或提供不越界的可靠判斷契約。
5. 將 #13 寫成「公開上線前硬閘」，並要求帳號層設定證據或 Perth 明確風險接受。

其餘 r2 修正可接受；#11、#19 正式撤回。
