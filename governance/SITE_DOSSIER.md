## 10. 採購與變更管線(v1.2 補 ── 料去哪領、改版怎麼知道、批怎麼發)

### 10.1 採購三律
1. 工地唯一採購場 = repo。規格 → `governance/specs/`;派工卡 → `governance/cards/`;素材(圖/JSON)→ `assets/`;文案凍結句 → 規格檔內逐字。不在 repo 的料 = 不存在,向設計師要,禁自造。
2. 工單引「路徑」不引「名稱」:卡上寫「文案見 governance/specs/xxx.md §n 逐字」。只給名稱沒給路徑 = 缺件,停手要路徑。
3. 雲端料(Airtable/Make/Dify 狀態)你搆不到 → 寫進回報請設計師代查,禁猜。

### 10.2 變更管線(pull-based:不靠人通知,靠開工動作)
- 任何規格/文案/價格變更,唯一入口:設計師改規格檔 + `governance/CHANGELOG.md` 加一行(日期|改了什麼|影響哪站/哪卡)→ 入 repo。
- 🔴 你的開工鐵律第 0 步:`git pull` + 讀 CHANGELOG 自上次讀後的新行。牆從藍改黃,你 pull 就知道,沒有「誰忘了通知」這種事故。
- 變更撞上進行中的卡 → 該卡停手,等設計師發「變更單(新卡)」;🔴 永不改工人手上的圖。
- 化石防制:新版入庫,同 commit 移除舊版或標 superseded ── 工地裡永遠只有一版。

### 10.3 發包模式(熟一站、凍一站、發一站)
- 一張卡 = 一個凍結批:發包時規格已凍(五件齊+文案定稿+驗收封閉)。你收到的卡若五件不齊 = 退回要規格,不開工。
- 未凍結的站(規格編製中)對你不存在 ── 別預研、別提前施工。
- 返工唯一合法形式 = 變更單新卡;沒有「拆掉重蓋」這種口頭工。
